# 📉 HW-3: Линейная классификация и введение в NLP

Этот репозиторий содержит решение домашнего задания №3 по курсу Машинного Обучения. Работа посвящена глубокому разбору логистической регрессии (реализация с нуля) и применению линейных моделей для решения задачи классификации текстов (NLP).


---

## 📑 Структура работы

### Часть 1. Логистическая регрессия своими руками
Реализован собственный класс `LogReg`, поддерживающий обучение через градиентный спуск.

**Ключевые особенности реализации:**
*   **Векторные вычисления:** Минимизация использования циклов, оптимизация через `numpy`.
*   **Два режима обучения:**
    *   `full`: Полный градиентный спуск.
    *   `stochastic`: Стохастический градиентный спуск (SGD).
*   **Критерии остановки:** По максимальному числу итераций или по евклидовой норме разности весов (`tolerance`).
*   **Сравнение:** Проведено сравнение с `sklearn.linear_model.LogisticRegression`.
*   **Визуализация:** Построены ROC-кривые, PR-кривые и визуализация предсказаний в 2D-пространстве с помощью **PCA** (метод главных компонент).

### Часть 2. Классификация текстов (NLP)
Решение задачи бинарной классификации на датасете **Kaggle: Disaster Tweets** (определение твитов о реальных катастрофах).

**Этапы работы:**
1.  **EDA (Разведочный анализ):**
    *   Анализ пропусков и баланса классов.
    *   Оценка информативности признаков `keyword` и `location`.
2.  **Бейзлайн (Baseline):**
    *   Простая конкатенация текста.
    *   Векторизация через `CountVectorizer` (Bag of Words).
    *   Модели: `LogisticRegression` и `SVC`.
    *   Метрика качества: **F1-score**.
3.  **Feature Engineering:**
    *   Тюнинг `CountVectorizer` (stop-words, min_df, max_features).
    *   Добавление категориальных признаков (`keyword`, `location`) через One-Hot Encoding.
    *   *Вывод:* Добавление "грязных" категорий (location) увеличило размерность, но не дало существенного прироста качества из-за шума.
4.  **Подбор гиперпараметров:**
    *   Использование `GridSearchCV` и `StratifiedKFold`.
    *   Перебор параметров регуляризации (`C`, `penalty='l1'/'l2'`) и весов классов.
5.  **Пайплайны (Pipelines):**
    *   Сборка полного цикла обработки данных через `ColumnTransformer` и `Pipeline` для автоматизации инференса.

## 📊 Ключевые результаты

| Модель | Метод | F1-Score (Test) | Комментарий |
|---|---|---|---|
| **LogReg (Baseline)** | Bag-of-Words (все слова) | ~0.79 | Отличный старт без настройки |
| **SVC (Baseline)** | Bag-of-Words | ~0.78 | Медленнее обучается |
| **LogReg (Tuned)** | Feature Selection (max_features) | ~0.76 | Снижение качества при сильном урезании словаря |
| **LogReg + Cats** | Text + OHE (Keyword/Location) | ~0.76 | Шум в Location помешал улучшению |
| **Final LogReg** | GridSearch (L2, C=0.5) | **~0.76-0.77** | Оптимальные параметры для смешанных данных |

## 💡 Выводы и рефлексия
1.  **Своя реализация vs Библиотека:** Собственный класс помогает понять математику градиентного спуска, но `sklearn` работает быстрее и стабильнее благодаря продвинутым солверам (`lbfgs`, `liblinear`) и встроенной регуляризации.
2.  **Качество данных:** В NLP качество предобработки (чистка текста, биграммы) часто важнее, чем сложность модели. Простое добавление признаков (как `location`) может навредить из-за проклятия размерности.
3.  **Линейные модели:** Для задач работы с текстом (высокая размерность, разреженные матрицы) простые линейные модели (LogReg, LinearSVC) работают очень эффективно и быстро, часто не уступая сложным алгоритмам.
