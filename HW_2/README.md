# Домашнее задание: Градиентный спуск — базовые концепции

Данный репозиторий содержит выполненное домашнее задание по теме "Градиентный спуск" (Gradient Descent). В ходе работы был пройден путь от реализации базовых математических функций до настройки продвинутых стратегий оптимизации с использованием расписаний (LR Schedulers).

## 📌 Основные цели работы
1.  **Реализация классического GD:** Написание чистого кода для оптимизатора с трекингом параметров, лосса и градиентов.
2.  **Дебаггинг:** Поиск и исправление ошибок в коде визуализации (Plotly).
3.  **Анализ ландшафтов:** Изучение поведения алгоритма на выпуклых (Quadratic) и невыпуклых (Rosenbrock) функциях.
4.  **Оптимизация гиперпараметров:** Исследование влияния Learning Rate и внедрение расписания (Inverse Time Decay) для стабилизации обучения.

## 🛠 Реализованный функционал

### 1. Математические модели
*   **Квадратичная функция:** Простая выпуклая поверхность $f(x, y) = x^2 + y^2$.
*   **Функция Розенброка:** Классический невыпуклый тест для оптимизаторов («банановый овраг»).
*   **Градиенты:** Реализованы аналитические производные для обеих функций в векторном виде.

### 2. Визуализация (Plotly)
Исправлены и настроены функции:
*   `plot_gd_3d`: Интерактивная 3D-поверхность с траекторией спуска, лежащей строго на рельефе.
*   `plot_gd_2d`: Контурный график (вид сверху) для анализа прохождения узких мест и оврагов.

### 3. Класс GradientDescentWithScheduler
Универсальный класс оптимизатора, поддерживающий:
*   **Постоянный шаг обучения.**
*   **Inverse Time Decay:** Уменьшение шага по формуле $\eta_k = \eta_0 / (1 + \text{decay} \cdot k)$, что позволяет сочетать быструю сходимость на старте и точность в конце.
*   **Логирование:** Полная история параметров, значений лосса и векторов градиента на каждой итерации.

## 📈 Ключевые выводы экспериментов

1.  **Чувствительность к Learning Rate:** 
    *   Слишком большой шаг на сложных рельефах приводит к «взрыву» градиента (ошибки `NaN`).
    *   Слишком маленький шаг делает обучение неэффективным (застревание на пологих участках).
2.  **Победа над «бананом» Розенброка:**
    *   Обычный GD часто не может дойти до минимума в узком овраге.
    *   Использование **Scheduler (затухания шага)** позволило достичь точности лосса $< 0.05$, так как алгоритм замедлялся при входе в узкий желоб и не «вылетал» из него.
3.  **Важность дебаггинга:** Чтение графиков лосса позволяет вовремя заметить осцилляции (прыжки) или взрыв градиента, что критически важно при обучении реальных нейросетей.
